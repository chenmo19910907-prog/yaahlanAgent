# Skill：Moments（动态）用例自动生成逻辑

> 本文档与仓库根目录 `SKILL.md` 的流程**一一对应**；差异仅在于 **强制业务上下文** 须落在 `documents/moments/`，并与 `rules/version_testcase_generation_rules.md` §1.2 对齐。

## 概览

在生成 **动态 / Moment** 相关测试用例时，以 **测试工程师视角** 保证可执行、可复现、可验证；**禁止**在未阅读 `documents/moments/` 对应文档前仅凭 PRD 片段盲写。

## 输入要求

- 需求文档为钉钉文档格式，且已开启访问权限（与根 `SKILL.md` 一致）。
- 若功能涉及 **列表 / 详情 / 发布 / 视频 / 热度 / 标签 / Profile / 互动通知 / 审核** 等，均视为动态域，适用本逻辑。

---

## 1. 设计覆盖策略（与 `SKILL.md` 一致）

在生成用例前，先在思考中明确覆盖维度（可在回复中简要列出）：

- **功能覆盖**：PRD 表格与正文中列出的全部板块、全部需求点（含一级/二级 Tab、外显入口、帧红点等）。
- **正反用例**：每个关键流程包含成功路径与失败/异常路径。
- **边界用例**：极端内容、长文、多图、弱网、杀进程、前后台切换、与语音房/1v1 冲突等（按 `documents/moments/` 中已列边界补充）。
- **专项用例**：性能、幂等、兼容性、安全（敏感内容、越权、审核链路）等。

---

## 2. 生成用例的操作步骤（对齐 `SKILL.md` 第 2 节）

### 2.1 参数说明

- `requirements_file_path`：钉钉需求文档地址（必填）。

### 2.2 处理流程

1. **读取需求**  
   - 使用钉钉文档读取能力（如项目内 `dingtalk-doc-read` 技能 / MCP `parse_document`）。  
   - 若返回「权限已过期」，按技能说明刷新 Cookie 后重试。

2. **【强制前置】业务上下文对齐（动态域特有，优先于模块表格拆解）**  
   - 依据 `rules/version_testcase_generation_rules.md` §1.2，在 `documents/moments/` 下按变更点选择并 **完整阅读** 对应文件（路径以仓库实际为准）：  
     - `basic module.md`：列表、详情、发布、Profile、互动通知、巡查、**超管动态审核**、帧红点等；**发版回归主文档**。  
     - `video.md`：视频动态全链路；与 `basic module.md` 中发布/列表/详情 **交叉阅读**。  
     - `hot.md`：热度、排序、衰减、hot 标签、发现列表、帖子皮肤、可见权限、@ 好友等。  
     - `label.md`：Topic/标签、分区、发现页、上下线联动等。  
   - **若仓库中缺失某文件**：在输出或备注中列出缺失路径；用例中标注「未找到 documents 对照，建议补充模块文档」，并仅做浅层推导。

3. **【模块提取】（动态专属）从 PRD 表格穷尽「动态域」模块**  
   逐行扫描需求表/原型目录，凡落入下列任一类 **均须单独成行提取为模块**，不得合并为笼统「动态优化」；用户若只口述子集，仍以 **PRD 全集** 为准：  
   - **入口与容器**：动态帧 / Room 或 IM 外显入口、发现·关注·我的（及 PRD 新增 Tab）、Profile 内动态流、话题分区 / 标签发现页入口。  
   - **内容与形态**：图文动态、视频动态、纯文本、转发/引用样式、运营位或卡片（若 PRD 有）。  
   - **主链路页面**：列表（Feed）、详情、发布 / 编辑、草稿箱（若有）。  
   - **互动与触达**：赞、评论、转发、收藏、@ 好友、互动通知列表与落地页、未读 / 红点。  
   - **分发与规则**：排序与刷新、热度 / hot 标签展示、可见范围、帖子皮肤、推荐与过滤（以 PRD）。  
   - **治理与审核**：用户侧举报 / 删除可见性；超管 **动态审核 Tab**、巡查、处置结果回流列表 / 详情。  
   - **配置与开关**：功能开关、灰度、与 Topic 上下线、热度策略变更等 PRD 列出的配置项。  
   - **冲突与协同**：与语音房、1v1、全屏播放、前后台切换相关的互斥或优先级（以 `documents/moments/` 为准）。

4. **【层级拆解】（动态专属）按「页面 → 区块 → 交互/数据」拆子功能**  
   每个已提取模块必须拆到 **可写单条用例** 的粒度；下列为 **动态域常用拆解维度**（按 PRD 取舍，未列则自建子点）：  
   - **列表 Feed**：Tab 切换；首屏与骨架；下拉刷新 / 自动刷新策略；分页与「无更多」；空态 / 错误态 / 重试；Cell 类型（图文 / 视频 / 运营卡）与复用；点击进入详情；举报或长按菜单（以 PRD）；预加载与内存（长列表基线）。  
   - **详情**：头图或视频区、全屏播放与手势、评论列表与分页、输入区与发送失败重试、删除 / 屏蔽 / 分享、审核中 / 下架态展示、返回列表后状态同步。  
   - **发布 / 编辑**：入口与权限；相册 / 相机 / 麦克风权限；多图顺序、视频选取与预览、编辑页回填；文案与话题 / 标签选择；可见范围；敏感与风控拦截；发布中 Loading、成功 / 失败 Toast、成功后回流列表位置（顶插 / 保持滚动以 PRD）。  
   - **视频专项**（与 `video.md` 对齐）：与语音房 / 1v1 并发、小窗 / 全屏切换、弱网、失败重试、敏感视频、通知缩略图与外显。  
   - **热度**（与 `hot.md` 对齐）：热度数展示、排序、衰减、发现列表规则、帖子皮肤、可见权限、@ 好友与列表一致性。  
   - **标签 / Topic**（与 `label.md` 对齐）：编辑页 Topic、带标签动态、标签分区、发现页、后台上下线对 C 端生效边界。  
   - **审核与巡查**：审核 Tab 列表字段、操作结果、再进列表 / 详情是否刷新；与普通用户可见内容差异。  
   每个 PRD 中 **独立标题、加粗小标题或独立段落** 对应至少一条用例或明确写明「依赖某条已覆盖」。

5. **【相似模块对齐】（动态专属）在动态域内部做「同源与模板」对齐**  
   对齐目标 **优先是** `documents/moments/` 下各文档之间的 **同一数据、同一交互在不同入口复用** 时不漂移；**不是**把营收活动里的地图、宝箱、瓜分等模块硬套到动态。具体约定：  
   - **多列表同源**：发现 / 关注 / 我的（及 PRD 其他 Feed）在 **Cell 结构、时间戳、互动数、媒体比例、错误重试** 上对齐 `basic module.md`；差异仅允许为 PRD 明示的 Tab 策略不同。  
   - **图文与视频对齐**：列表 → 详情 → 再进发布编辑的 **字段口径、删除/审核态、互动数回写** 须 `basic module.md` 与 `video.md` **交叉一致**；禁止列表可播详情不可播等同源矛盾。  
   - **热度与 Feed 对齐**：列表上展示的热度、hot 标签、排序规则与 `hot.md`、发现页规则 **同一套配置**；改版时显式对照两文档相关段落。  
   - **标签与分区对齐**：编辑页所选 Topic / 标签与列表角标、分区 Feed、发现页入口在 `label.md` 口径下 **一致**；Topic 上下线影响范围写清。  
   - **通知与内容对齐**：互动通知缩略图、跳转落地页与对应动态详情 **同一 id、同一状态**（含已删 / 已下架）。  
   - **可选：榜单类骨架**：仅当 PRD **明确** 动态内嵌「排行式列表」时，可局部借用 `templates/榜单.md` 的 **分页、吸底、计值展示** 等子维度；**不得**用活动榜单的定榜发奖、瓜分等业务逻辑替代动态用例结构。

6. **通用规则补充**  
   - 除 PRD 与 `documents/moments/` 外，须结合 `rules/testcase_generation_rules.md` 中的通用条目（正向/反向/边界/交互等）做补充，不重复造轮子。

7. **用例格式（与 `SKILL.md` 一致；不要求优先级）**

| 字段     | 说明 |
|----------|------|
| 用例ID   | 唯一标识；建议带域前缀便于检索，如 `MOMENT_001`（或项目约定前缀） |
| 功能模块 | 与 PRD 模块及 `documents/moments/` 章节对应 |
| 用例标题 | 一句话概括验证点 |
| 测试步骤 | 按 1. 2. 3. 分行，可执行 |
| 期望结果 | 界面反馈、接口状态、埋点（若有）、无崩溃与越权 |

8. **输出位置**  
   - 默认写入 `temporary_testcase/`，文件名建议带需求标识，例如：`Moments_<版本或需求名>_测试用例.md`。

---

## 3. 【生成前校验】输出前自检清单（与 `SKILL.md` 一致并加强动态域）

- PRD 表格中 **每一行模块** 是否都有对应用例？  
- 各模块下 **加粗标题 / 独立段落** 的子功能是否覆盖？  
- 是否已按变更点阅读 **`documents/moments/` 中至少一个** 主文档，且在涉及视频时 **同时** 对照 `video.md` 与 `basic module.md`？  
- 是否已按上一节「相似模块对齐」完成 **动态域内部** 多入口、图文与视频、热度与标签、通知与详情之间的口径核对（而非仅套用活动模板）？  

---

## 4. 输出整理（与 `SKILL.md` 一致）

- 使用 `testcase-to-excel` 技能：从 `temporary_testcase/` 读取生成的 Markdown/CSV，通过 MCP `dingtalk-excel-write` 写入用户提供的 `testcase_file_path`。  
- 大批量时分批 `write_sheet_data`，避免单次超限。
