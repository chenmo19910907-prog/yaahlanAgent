# 钉钉历史用例文档 → Markdown 转换规则

本文档约定：从钉钉上的**历史测试用例**（多为 Excel 表格，少数为在线文档）读取内容，整理为本地 **Markdown**，字段以 **功能模块、用例步骤描述、预期结果** 为核心，便于版本管理、diff 与后续生成/合并用例。

---

## 1. 适用范围与目标结构

### 1.1 适用场景
- 迁移钉钉表格/文档中的存量用例到仓库 `temporary_testcase/`（或团队约定的目录）。
- 为自动生成、用例评审提供「已对齐列含义」的单一事实来源。

### 1.2 输出 Markdown 必备语义列（逻辑列名）

| 逻辑列名 | 含义 | 填写要求 |
|---------|------|----------|
| **功能模块** | 用例所属模块或子功能 | 与 PRD/页面模块一致；同一模块在文档中连续出现（见 `testcase_generation_rules.md` 中模块划分约定）。 |
| **用例步骤描述** | 可执行的操作步骤 | 使用有序列表语义：`1.` `2.` …；单元格内多行合并为一步时，用 `<br>` 或 Markdown 换行（与团队统一即可）。 |
| **预期结果** | 与步骤对应的可验证结果 | 写清界面/数据/提示；多预期与步骤对应时可用换行或分号区分。 |

可选扩展列（若源表存在则保留，可放在表格最前或最后，但**不得拆散**上述三列语义）：

- 用例编号、优先级、前置条件、备注、维护人等——统一追加在表头，整表列顺序各 Sheet 保持一致。

## 2. 数据来源与读取方式

### 2.1 钉钉 Excel（优先）

历史用例多数在 **钉钉多维表/电子表格** 中。

1. 确认文档为 Excel 类型 URL（`alidocs.dingtalk.com` 下表格链接）。
2. 使用 MCP **`user-dingtalk-excel-read`**，工具 **`get_sheet_info`**：
   - **必填**：`url` = 钉钉 Excel 完整 URL。
   - **可选**：`sheetname` = Sheet 名称；不传则使用第一个 Sheet。
   - **鉴权**：`aegisKey` / `aegisSecret` / `workid` 可省略，默认读环境变量 `DINGTALK_AEGIS_KEY`、`DINGTALK_AEGIS_SECRET`、`DINGTALK_WORKID`。

### 2.2 钉钉普通文档（表格嵌在正文）

当用例写在 **钉钉文档**（非 Excel）里时：

1. 使用 MCP **`user-dingtalk-doc`**，工具 **`parse_document`**，`url_or_node_id` 填文档 URL 或 NODE_ID；Cookie 过期处理见项目技能 `.cursor/skills/dingtalk-doc-read/SKILL.md`（`refresh_cookie` 后重试）。
2. 从解析产物（如 `*_content.json` / `*.html`）中**定位表格或列表**，手工或脚本抽取为「行 = 用例」的结构，再按第 3、4 节映射与排版。

## 3. 表头映射（源列 → 逻辑列）

源表列名往往不统一，按**模糊匹配**映射到逻辑列；**命中多个候选时，以表头从左到右第一次匹配为准**，并在 MD 文首「元信息」备注实际映射。

建议别名表：

| 逻辑列 | 可识别的源表头关键词（含部分匹配即可） |
|--------|----------------------------------------|
| 功能模块 | 模块、功能模块、子模块、所属模块、菜单、功能 |
| 用例步骤描述 | 步骤、测试步骤、操作步骤、用例步骤、Case步骤、case步骤、操作流程 |
| 预期结果 | 预期、预期结果、期望结果、校验点、结果 |

**未映射列**：原样保留列名，作为扩展列输出，避免信息丢失。

**空行**：与 `get_sheet_info` 行为一致，跳过空行；不人为插入空用例行。

### 3.1 历史噪音数据过滤（强制）

读取历史文档时，以下类型属于非目标测试用例，**必须过滤，不读取到输出 MD**：

- 覆盖率任务
- 老版本
- 翻译
- 镜像case（含「镜像 case」「镜像Case」等大小写/空格变体）

过滤命中范围建议如下（任一命中即过滤）：

- 功能模块列
- case步骤描述（若存在）

## 4. Markdown 文件结构与排版

### 4.1 文件命名与存放

- 目录：`history_testcase/`
- 文件命名：`{sheet名称}.md`（一个 Sheet 对应一个文件）
- 示例：
  - `history_testcase/礼物榜.md`
  - `history_testcase/房间榜.md`
- 命名规范：
  - 使用钉钉文档中的原始 Sheet 名称作为文件名主体。
  - 若名称含文件系统不支持字符（如 `/`、`:`），仅替换非法字符为 `_`，其余保持原样，避免语义丢失。
- 文件开头增加简短元信息（YAML 或二级标题均可），至少包含：
  - 钉钉源 URL
  - 导出时间（ISO 或 `YYYY-MM-DD`）
  - Sheet 名（若多 Sheet）
  - 表头映射说明（如有别名）

### 4.2 按功能模块分节（强制）

与 `rules/testcase_generation_rules.md` 中「按模块组织」一致：

1. 读取全部行后，**按「功能模块」分组**。
2. 每个模块使用：`## 功能模块：{模块名}`（模块名取自该列；若为空，归入 `## 功能模块：未分类`）。
3. 模块内用 Markdown 表格呈现，**表头固定为**：

```markdown
| 功能模块 | 用例步骤描述 | 预期结果 |
```

（若保留扩展列，在右侧追加，例如 `| 功能模块 | 用例步骤描述 | 预期结果 | 优先级 | 备注 |`。）

4. 单元格内换行：优先使用 `<br>`，以保证 GitHub/Cursor 预览下单格多行可读；团队若统一用 HTML 禁止，可改为单行 + 分号。

### 4.3 步骤列格式

- 从 Excel 导入时，若已为多行文本，合并为一条用例的步骤时，编为 `1. … 2. …`。
- 禁止仅粘贴无编号大段文字而不分段；步骤应可被测试执行人员逐步照做。

---

## 5. 转换流程检查清单

- [ ] 已确认钉钉文档类型（Excel / 普通文档），并选用对应 MCP。
- [ ] 表头已映射到「功能模块 / 用例步骤描述 / 预期结果」，歧义已写在文首备注。
- [ ] 按模块分节，同模块行连续，无交叉打乱。
- [ ] 行数与源数据一致（过滤空行后），无整行静默丢失。
- [ ] 文件已保存到 `history_testcase/`，命名为 `sheet名称.md`。

---

## 6. 异常与人工介入

| 情况 | 处理 |
|------|------|
| Excel API 鉴权失败 | 检查环境变量与工作台权限；仍失败则记录错误信息，停止自动转换，改人工导出 CSV 后按同样列映射手搓 MD。 |
| 文档 Cookie 过期 | 按 `dingtalk-doc-read` 技能刷新 Cookie 后重试 `parse_document`。 |
| 源表无「模块」列 | 全文归入「未分类」，或根据「用例标题/页面」列推断模块并在备注中说明**推断规则**。 |
| 一单元格混有多条用例 | 拆成多行或多条表格行；无法拆分则标记「需业务确认」在备注列。 |

---

## 7. 与其他规则的关系

- **模块划分、可读性**：遵循 `rules/testcase_generation_rules.md`（若该文件含「模块划分与文档结构」章节，以最新版为准）。
- **优化类需求**：当本次是「优化/改版」而非全新功能时，历史 MD **仅供检索与抽取**，生成新用例须按 `testcase_generation_rules.md` 中「优化类需求」：**结合优化点改写相关历史条目，禁止不经筛选全量复制历史用例**。
- **从 MD 再写回钉钉 Excel**：见 `.cursor/skills/testcase-to-excel/SKILL.md`，注意列顺序需与钉钉目标表一致。
