# 测试用例自动生成器 (Test Case Generator)

这个技能可以自动从钉钉产品需求文档生成完整的测试用例文档，支持多种文档格式（Excel表格、普通文档），并严格遵循预定义的测试用例设计规则。

## 何时使用

- 需要从钉钉文档生成测试用例时
- 产品需求文档更新，需要同步更新测试用例时
- 需要标准化测试用例输出格式时
- 大量测试用例需要批量生成时

## 适用场景

- **产品需求评审**：基于PRD文档快速生成测试用例框架
- **迭代开发**：新功能上线前自动生成回归测试用例
- **质量保障**：确保测试用例覆盖率和标准化
- **文档同步**：需求变更时自动更新相关测试文档

## 执行流程

### 1. 输入处理
```
用户提供钉钉文档URL → 技能识别文档类型 → 调用相应解析工具
```

### 2. 内容解析
```
Excel文档 → mcp_dingtalk-excel-read → 提取Sheet数据
普通文档 → mcp_dingtalk-doc → 解析文档内容
```

### 3. 规则应用
```
读取测试用例设计规则 → 分析需求内容 → 匹配测试场景 → 生成测试用例
```

### 4. 输出生成
```
标准化格式转换 → 质量检查 → 输出到指定目录 → 生成统计报告
```

## 支持的文档类型

| 文档类型 | 解析工具 | 输出格式 |
|---------|---------|---------|
| Excel表格 | `mcp_dingtalk-excel-read` | Markdown表格 |
| 普通文档 | `mcp_dingtalk-doc` | 结构化Markdown |
| 混合文档 | 智能识别 | 统一Markdown |

## 使用方法

### 基本用法
```
/testcase-generator https://alidocs.dingtalk.com/i/nodes/XXX
```

### 高级用法
```
/testcase-generator https://alidocs.dingtalk.com/i/nodes/XXX --rules soulchill_revenue_testcase_rules --output soulchill_revenue_testcase_output
```

### 参数说明

| 参数 | 说明 | 默认值 | 示例 |
|------|------|--------|------|
| `url` | 钉钉文档URL | 必需 | `https://alidocs.dingtalk.com/i/nodes/XXX` |
| `--rules` | 规则文件路径 | `soulchill_revenue_testcase_rules` | `--rules custom_rules` |
| `--output` | 输出目录 | `soulchill_revenue_testcase_output` | `--output testcases` |
| `--format` | 输出格式 | `markdown` | `--format excel` |
| `--template` | 模板文件 | 内置模板 | `--template custom.md` |

## 生成规则说明

### 用例结构规范
每个生成的测试用例都包含以下标准字段：

```markdown
| 编号 | 子功能模块 | 测试步骤 | 预期结果 | 优先级 | 预估时间 |
|------|-----------|---------|---------|-------|----------|
| AUTH_LOGIN_001 | 登录验证 | 1. 步骤1<br>2. 步骤2 | 预期结果描述 | P0 | 3分钟 |
```

### 优先级标准
- **P0**：核心功能，影响系统正常使用
- **P1**：重要功能，用户常用功能
- **P2**：一般功能，辅助功能
- **P3**：边缘功能，低频使用

### 覆盖范围
- **功能覆盖**：≥95% 的业务功能点
- **流程覆盖**：正常流程 + 异常流程 + 边界条件
- **数据覆盖**：有效数据 + 无效数据 + 边界值
- **平台覆盖**：多设备 + 多系统 + 多网络环境

### 榜单用例（Yaahlan / 活动页榜单）
当用户要生成 **榜单** 相关测试用例，或需求/对话中明确涉及 **活动榜单** 等场景时，**必须先阅读** 仓库内 `templates/yaahlan榜单.md`（及通用参考 `templates/榜单.md` 的列结构：编号、子功能模块、测试步骤、预期结果）：
- 按 **B 列「子功能模块/功能模块」** 维度归类，与现表中的模块划分（如「榜单值统计逻辑」「全服用户送礼/收礼榜」「弹窗热区交互」「榜单奖励」等）对齐。
- 输出用例的 **步骤、预期、颗粒度** 与 `yaahlan榜单.md` 中已梳理用例保持同一风格，再按当前 PRD 增量补全或调整。

## 错误处理

### 常见错误及解决方案

| 错误类型 | 错误信息 | 解决方案 |
|---------|---------|---------|
| 文档访问失败 | "无法访问钉钉文档" | 检查URL有效性，确认权限设置 |
| 解析失败 | "文档格式不支持" | 确认文档为支持的格式（Excel/普通文档） |
| 规则文件缺失 | "找不到设计规则文件" | 确认规则文件路径和文件名正确 |
| 输出权限不足 | "无法写入输出目录" | 检查目录权限，确认写权限 |

### 降级处理
- **文档无法访问**：提示用户手动提供文档内容
- **解析失败**：提供基础模板让用户手动完善
- **规则缺失**：使用内置默认规则生成

## 扩展能力

### 自定义规则
支持加载自定义测试用例设计规则：

```yaml
# custom_rules.yaml
testcase:
  structure:
    fields: [编号, 模块, 步骤, 预期, 优先级, 时间]
  priority:
    critical: P0
    important: P1
    normal: P2
  coverage:
    functional: 0.95
    process: 0.90
```

### 模板定制
支持自定义输出模板：

```markdown
<!-- custom_template.md -->
# {{project_name}} 测试用例 v{{version}}

## 测试范围
{{test_scope}}

## 测试用例
{{test_cases_table}}
```

### 集成能力
- **CI/CD集成**：自动生成测试用例作为流水线一部分
- **测试管理工具集成**：导出到TestRail、Zephyr等工具
- **代码生成**：基于测试用例生成自动化测试脚本
