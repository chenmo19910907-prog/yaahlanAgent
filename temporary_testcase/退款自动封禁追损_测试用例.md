# 退款自动封禁追损 测试用例

| 功能模块 | 测试步骤 | 预期结果 |
|----------|----------|----------|
| 【实时处理-触发阈值】 | 结薪周期内，退款用户累计退款金额恰好达到 $49.00 | 实时触发：本人账号封禁、充值设备封禁、本人和设备关联用户加退款黑名单 |
| | 退款金额累计 $48.99（差一分未达阈值） | 不触发封禁和黑名单，无任何处理 |
| | 同结薪周期内发生多笔退款，各笔金额较小，累计恰好达 $49.00 | 多笔累计正确，达阈值后实时触发 |
| | 同周期内已触发封禁（累计退款 $49）后，继续退款至 $60 | 不重复触发封禁和黑名单操作，账号和设备保持原封禁状态 |
| | 上一结薪周期退款 $30，新周期开始后再退款 $30 | 周期内退款额不跨周期累计，新周期重新计算，本次 $30 不触发 |
| 【实时处理-封禁本人账号】 | 退款触发阈值后，用退款用户账号尝试登录/使用 App | 账号被封禁，无法正常使用 |
| | 检查封禁原因记录 | 封禁原因精确为"结薪周期内退款达49美元封禁账号" |
| 【实时处理-封禁充值设备】 | 退款触发阈值后，检查退款订单充值时使用的设备状态 | 该充值设备被封禁 |
| | 退款订单的充值设备存在 mmuidv3，检查封禁记录中的设备ID字段 | 设备ID使用 mmuidv3 |
| | 退款订单的充值设备无 mmuidv3 只有 mmuid，检查设备ID字段 | 设备ID使用 mmuid |
| | 验证封禁原因文案 | 封禁原因精确为"{退款用户user_id}结薪周期内退款达49美元封禁充值设备{设备ID}" |
| 【实时处理-设备关联用户黑名单】 | 退款触发阈值后，充值设备关联了多个其他用户，查看这些用户黑名单状态 | 所有关联用户全部加入退款黑名单 |
| | 验证关联用户的黑名单原因 | 黑名单原因精确为"与退款用户{user_id}共用充值设备" |
| | 验证退款用户本人的黑名单原因（与关联用户区分） | 退款用户本人黑名单原因为"本人退款达49美元" |
| | 充值设备关联用户中有部分已在黑名单中，退款再次触发 | 已在黑名单中的用户不重复添加，其余用户正常加入 |
| 【实时处理-大R预警】 | 充值设备关联用户中有公会长，退款触发阈值 | 钉钉群收到【退款设备关联大R】预警消息 |
| | 充值设备关联用户中有 VIP6 用户（精确等于 VIP6），退款触发阈值 | 钉钉群收到【退款设备关联大R】预警消息 |
| | 充值设备关联用户中有 VIP7 及以上用户，退款触发阈值 | 钉钉群收到【退款设备关联大R】预警消息 |
| | 同一充值设备关联多个大R用户（如 2 个公会长），退款触发阈值 | 每个大R用户各发一条预警，共发 2 条 |
| | 验证大R预警消息字段完整性（关联用户是公会长） | 包含：用户ID、用户身份（xxx公会长）、VIP等级、退款用户ID、退款设备ID（优先 mmuidv3）；内容准确无误 |
| | 验证大R预警消息字段完整性（关联用户是主播身份 VIP6+） | 用户身份字段展示"主播"，VIP等级字段展示正确 |
| | 充值设备关联用户均为普通用户（非公会长、非 VIP6+） | 不发送大R预警消息 |
| 【结薪日处理-阈值触发】 | 结薪日时，某用户当前结薪周期内退款金额恰好达 $99.00 | 触发该用户的集中收礼人检测逻辑 |
| | 退款金额为 $98.99（未达 $99） | 不触发集中收礼人检测 |
| | 结薪日时，退款已在实时处理阶段封禁（累计 $49），继续退款至 $99，到结薪日 | 仍触发结薪日集中收礼人检测（两条规则独立触发） |
| 【结薪日处理-集中收礼人判定】 | 近 60 天内，某账号收到退款用户礼物占其总收礼金额 =90%，且收到退款礼物价值 =$49 | 恰好满足两个边界条件，该账号被判定为集中收礼人，封禁并加黑名单 |
| | 近 60 天内占比 89%（差一点未达 90%），收到退款礼物价值 $100 | 占比不足，不被判定为集中收礼人 |
| | 近 60 天内占比 95%，但收到退款礼物价值 $48.99（未达 $49） | 金额不足，不被判定为集中收礼人 |
| | 集中收礼人的退款用户范围：包含近 60 天内所有累计退款超 $49 的用户（不仅是本次触发的那个） | 计算时包含多个退款用户的送礼金额，验证跨多个退款用户的汇总计算正确 |
| | 集中收礼人账号已在退款黑名单中，结薪日再次触发判定 | 仍执行封禁和黑名单操作（幂等处理），不因已在黑名单中而跳过 |
| 【结薪日处理-封禁与黑名单原因】 | 集中收礼人被判定后，检查封禁原因 | 封禁原因精确为"集中收到退款用户{user_id逗号分隔}送礼"（多个退款用户ID逗号分隔） |
| | 检查集中收礼人黑名单原因 | 黑名单原因精确为"集中收到退款用户{user_id逗号分隔}送礼" |
| 【结薪日处理-集中收礼人预警】 | 集中收礼人为公会长 | 钉钉群收到【退款集中收礼人】预警消息 |
| | 集中收礼人为 VIP6+ 用户 | 钉钉群收到【退款集中收礼人】预警消息 |
| | 验证【退款集中收礼人】消息字段完整性 | 包含：用户ID、身份、退款用户ID（逗号分隔多个）、收到退款用户礼物金额、封禁原因、加黑名单原因 |
| | 集中收礼人为普通用户（非公会长、非 VIP6+） | 不发送集中收礼人预警消息，但仍执行封禁和黑名单 |
| 【手动批量加黑名单】 | 后台手动批量提交 uid 列表及对应原因 | 加黑名单成功；各用户黑名单原因与提交内容完全一致 |
| | 提交的 uid 列表中部分用户已在黑名单中 | 已在黑名单用户不报错/不重复加入；其余用户正常加入 |
| 【手动移出黑名单】 | 手动将用户从退款黑名单中移出 | 移出成功，该用户不再出现在黑名单中 |
| | 移出后第 1 天，用户再次满足自动触发条件 | 豁免期内（16天）不自动加入黑名单 |
| | 移出后第 15 天，用户再次满足自动触发条件 | 仍在 16 天豁免期内，不自动加入黑名单 |
| | 移出后第 16 天，用户再次满足自动触发条件 | ⚠️ 边界待确认：第 16 天是否算豁免内（需产品确认是否为"满16天"或"第17天起"恢复） |
| | 移出后超过 16 天，用户再次满足自动触发条件 | 豁免期已过，正常自动加入黑名单 |
| 【黑名单持久化】 | 结薪周期结束后，查看退款黑名单 | 黑名单不自动清空，数据跨周期持续保留 |
| | 跨多个结薪周期后，黑名单数据仍在 | 无论经过多少个结薪周期，黑名单均不自动清空 |
| 【算薪处理-薪资计算】 | 结薪日，退款黑名单主播当期算薪 | 参与主播粒度薪资计算（数据存在），但不参与应得薪资计算（应得薪资为 0） |
| | 退款黑名单主播被手动移出后，次结薪周期再次算薪 | 不再被标记为黑名单，应得薪资恢复正常计算 |
| 【算薪处理-导出报表】 | 导出自动算薪 combined_report，查看「风控主播表」 | 退款黑名单主播出现在该表中 |
| | 同一主播有多个黑名单原因（如既有设备关联又有集中收礼），查看风控原因字段 | 多个原因以逗号分隔，全部展示，无遗漏 |
| 【算薪处理-数仓同步】 | 结薪后检查数仓对应表 | 退款黑名单主播数据已落表并同步到数仓，字段内容与黑名单一致 |
