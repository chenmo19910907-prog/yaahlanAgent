# BD系统 测试用例（第二份 - 边界与异常角度）

> 需求版本：Yaahlan-2.5.5 | 覆盖角度：时间边界、状态流转、权限安全、关联影响、幂等并发、数值精度、数据一致性

| 功能模块 | 测试步骤 | 预期结果 |
|---------|---------|---------|
| 【大R注册天数边界】 | 大R用户注册后第30天23:59（沙特时间）查看操作栏 | 打款按钮尚未出现，状态不为"待审批" |
| | 大R用户注册后第31天00:00（沙特时间）查看操作栏 | 打款确认和拒绝按钮出现，状态变为"待审批" |
| | 大R用户在注册后第29天达到VIP5，第31天00:00后查看奖励档位 | 奖励按注册30天内最高VIP等级（VIP5）计算，不以当前等级重新计算 |
| | 大R用户注册后第30天升到VIP6（超过30天范围），查看奖励档位 | 奖励仍按第30天内记录的VIP等级计算，第31天后VIP变化不影响奖励 |
| 【公会周期边界】 | 周期1计算结束当天23:59，查看操作栏 | 周期1打款按钮尚未出现 |
| | 周期1结束后次日00:00，查看操作栏 | 周期1打款和拒绝按钮出现，状态变为"周期1待审批" |
| | 周期2计算结束当天23:59，查看操作栏 | 周期2打款按钮尚未出现，周期1已处理状态不变 |
| | 周期2结束后次日00:00，查看操作栏 | 周期2打款和拒绝按钮出现，状态包含"周期2待审批" |
| 【BD豁免期边界】 | BD被移除后第15天23:59，重新申请BD | 申请页正常展示，可提交申请 |
| | BD被移除后第16天00:00后，重新申请BD | 申请页正常，可提交申请（移除后可重新申请，与挖猎黑名单豁免不同） |
| 【手动移出黑名单豁免期边界】 | 用户被手动移出退款黑名单后第15天23:59（豁免期内），再次满足自动加入条件 | 不自动加入黑名单，豁免期保护生效 |
| | 用户被手动移出后第16天00:00（豁免期结束），再次满足自动加入条件 | 正常自动加入黑名单 |
| 【大R状态流转】 | 新增挖猎记录后立即查看状态 | 状态为空/无待审批（尚未到注册31天） |
| | 到注册31天00:00后，状态变为待审批，点击同意 | 状态流转：待审批 → 已同意工单进行中 |
| | 工单审批通过后查看状态 | 状态流转：已同意工单进行中 → 工单通过已打款 |
| | 在"已同意工单进行中"状态下，点击拒绝并确认 | 状态流转：已同意工单进行中 → 已拒绝；工单中该笔不生效 |
| | 工单审批系统拒绝后查看状态 | 状态流转：已同意工单进行中 → 工单被拒绝 |
| | 处于"已拒绝"状态的记录，查看操作栏 | 所有操作按钮隐藏，不可再次同意或修改 |
| 【公会状态流转】 | 周期1处于"工单通过已打款"，周期2进入"待审批"，分别查看状态栏 | 周期1与周期2状态独立显示，互不干扰 |
| | 周期1"已拒绝"，查看周期2打款按钮是否可用 | 周期1状态不影响周期2，周期2打款按钮正常展示 |
| | 对处于"周期1工单通过已打款"的记录，尝试再次点击周期1打款 | 周期1打款按钮不可见，无法重复操作 |
| 【操作权限】 | 使用非萨克、非运营账号尝试访问挖猎运营页URL | 无法访问，页面提示无权限或跳转登录 |
| | 萨克账号登录后台，查看挖猎运营菜单是否可见 | 菜单可见，可正常进入 |
| | AM账号（非萨克）登录后台，查看挖猎运营菜单 | 菜单不可见或无法进入 |
| | 萨克执行同意打款操作，查看操作记录日志 | 后台操作记录中包含：操作人ID、操作时间、操作类型（同意打款）、挖猎用户ID |
| | 萨克执行拒绝操作，查看操作记录日志 | 后台操作记录中包含拒绝原因和操作人信息 |
| 【关联影响-大R被封禁】 | 被挖猎的大R用户在奖励审批前被封禁，奖励状态查看 | 封禁不影响BD奖励流程，奖励仍可正常审批发放（或标注疑问：产品需确认封禁用户是否影响BD奖励） |
| | 被挖猎的大R注册30天内账号被注销，查看奖励档位 | 以注销前记录的最高VIP等级计算（需产品确认） |
| 【关联影响-公会解散】 | 公会挖猎期间，公会被解散，查看对应挖猎记录 | 挖猎记录保留，历史薪资数据不变；后续周期薪资为0（需产品确认） |
| | 公会长被更换后，查看对应挖猎记录的公会长ID | 挖猎记录中公会长ID是否更新（需产品确认是否跟随变动） |
| 【关联影响-BD账号异常】 | BD账号本人被封禁后，其挖猎列表在后台是否仍可查看 | 挖猎列表仍可查看，BD信息展示"BD已移除"或标注封禁状态（需确认） |
| | BD账号本人注销后，其下挖猎用户的奖励状态 | 奖励已审批通过的不受影响；未审批的是否继续处理（需产品确认） |
| 【幂等性】 | 在同意打款弹窗确认后立即快速多次点击确认按钮 | 只生成一条工单，不重复提交 |
| | 工单审批中状态下，重复调用同意接口（如通过抓包重放） | 服务端幂等处理，不重复生成工单，返回已存在工单信息 |
| | 短时间内多次点击新增挖猎按钮并快速确认 | 只新增一条记录，不重复插入 |
| | 同一BD同一用户短时间内通过多个设备同时点击申请BD按钮 | 只创建一个申请记录，不重复创建 |
| 【数值精度-奖励档位临界值】 | 大R注册30天内累充金额恰好等于某奖励档位最低值 | 对应档位奖励触发，钻石和美金数量与规则一致 |
| | 大R注册30天内累充金额低于最低档位1美分 | 未达最低档位，显示"无奖励" |
| | 公会周期1薪资恰好等于某奖励档位临界值 | 对应档位奖励计算正确 |
| | 公会周期薪资含预提后恰好跨越档位边界（不含预提时在下一档，含预提时在上一档） | 薪资以含预提的值计算，档位以含预提后的金额对应 |
| 【数据一致性】 | 后台手动修改某条大R挖猎打款金额后，BD在App端查看该条目 | App端BD中心显示的奖励金额与后台修改后保持一致 |
| | 萨克在后台将某BD移除后，该BD立即打开App | BD中心入口消失，不展示（或有短暂延迟，需确认实时性） |
| | 新用户通过BD专属链接注册后，BD在App端BD中心查看 | 新用户出现在BD大R列表，进入平台时间和注册时间显示正确 |
| | 后台大R挖猎列表中显示的VIP等级与App端用户实际VIP等级 | 后台显示注册30天内的VIP等级快照，不随用户当前等级变化 |
| | 公会第一周期薪资在后台列表中的数值与算薪系统数据 | 数值一致，误差为0 |
| 【专属链接唯一性】 | 两位不同BD的专属链接，用同一用户ID分别点击两个链接后注册 | 用户只能与最先点击的BD关联（或以最后一次为准，需产品确认） |
| | 已注册用户点击BD专属链接 | 不重复关联，不纳入该BD挖猎（需产品确认） |
| | BD专属链接在不同平台（安卓/iOS）点击 | 分别跳转对应应用商店，下载注册后关联逻辑一致 |
| 【BD申请重复操作】 | 已申请BD且处于"已申请"状态的用户，再次点击申请 | 申请页维持"已申请"状态，不允许重复提交 |
| | 已被拒绝的BD申请用户，通过其他客服再次获取申请入口并申请 | 申请页显示已拒绝状态，或允许重新申请（需产品确认重新申请逻辑） |
| | 已成为BD的用户，尝试再次通过申请入口申请 | 进入申请页直接展示BD中心入口，不允许重复申请 |
| 【后台导出数据准确性】 | 导出大R挖猎列表，校验导出Excel中累充金额字段 | 导出金额与页面展示一致，含小数时精度不丢失 |
| | 按时间段导出打款记录，边界日期当天的记录是否包含 | 起始日和结束日当天的打款记录均包含在导出结果中 |
| | 同时有多人进行导出操作 | 各自导出互不影响，导出内容均正确 |
| 【新老版本交互】 | 老版本App（无BD功能）用户收到BD专属链接 | 跳转至应用商店提示更新，或直接跳转下载新版（需产品确认） |
| | BD功能未开放地区用户点击专属链接 | 跳转后不展示BD相关入口（若有地区限制，需产品确认） |
| 【大小屏适配】 | 在平板/大屏设备上查看BD中心大R列表 | 页面布局正常，列表无错位、无裁切 |
| | 在小屏设备上查看BD中心，列表字段较多时 | 支持左右滑动或字段自适应，不出现内容遮挡 |
