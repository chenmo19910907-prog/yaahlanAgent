# mkwebview 域名替换功能 测试用例

**需求背景**：技术优化，mkwebview 新增域名替换与离线包反查功能，通过 Firebase RemoteConfig 动态下发备用域名，并开启 multiPkg 功能（白名单外网测试）。

---

| 功能模块 | 测试步骤 | 预期结果 |
|----------|----------|----------|
| **【基础】Web/H5 正常展示** | 正常网络环境下，遍历 App 内主要 H5/WebView 页面入口（首页、个人页、活动页、充值页等） | 所有 H5 页面正常加载，无白屏、无加载失败 |
| | 观察页面内图片、文字、按钮等元素 | 页面内容完整展示，样式正常，无元素错位 |
| **【基础】Bridge 调用正常** | 进入含 Bridge 调用的 H5 页，触发 JS → Native 方向调用（如获取用户信息、获取设备信息、调用分享等） | Native 正确响应，H5 侧回调数据正常，功能正常执行 |
| | 触发 Native → H5 推送场景（如事件通知回调） | H5 侧正确接收消息，页面响应符合预期 |
| | 验证 Bridge 调用无兼容性问题（iOS / Android 各覆盖） | iOS 与 Android 表现一致，无特定平台 Bridge 异常 |
| **【H5域名替换】正常链路对照** | 不屏蔽任何域名，打开 H5 页面，观察请求使用的域名 | 使用主域名正常访问，页面加载正常（作为对照基准） |
| **【H5域名替换】主域名屏蔽 → 备用域名切换** | 通过 Charles/代理工具屏蔽 H5 主域名，确认 Firebase RemoteConfig 已配置备用域名，重新打开 H5 页面 | 客户端检测到主域名不可用，自动切换到备用域名，H5 页面正常加载，无白屏 |
| | 切换备用域名后，观察网络请求 | 请求域名已替换为备用域名，无主域名请求 |
| **【H5域名替换】备用域名下功能完整性** | 在备用域名环境下，依次执行核心业务操作（浏览内容、登录态保持、核心功能操作） | 业务功能完整可用，登录态正常，数据展示正确 |

| **【H5域名替换】主域名恢复后行为** | 先屏蔽主域名触发备用域名，再恢复主域名，重新打开 H5 | 以技术方案实际策略为准（确认后更新）；App 不崩溃，功能正常 |
| **【CDN域名替换】正常链路对照** | 不屏蔽 CDN 域名，打开含图片/JS/CSS 资源的 H5 页面 | 所有 CDN 资源正常加载，页面样式与交互正常（作为对照基准） |
| **【CDN域名替换】主CDN屏蔽 → 备用CDN切换** | 屏蔽主 CDN 域名，确认 RemoteConfig 已配置备用 CDN，重新打开 H5 页面 | CDN 资源通过备用 CDN 域名加载，无 404 资源错误 |
| | 备用 CDN 下观察图片资源 | 图片完整加载，无破图 |
| | 备用 CDN 下观察 JS/CSS 资源 | 页面样式正常，JS 功能正常执行，无脚本报错 |
| **【CDN域名替换】主CDN+备用CDN均不可用** | 同时屏蔽主 CDN 域名和备用 CDN 域名 | 页面有合理降级展示（如占位图），不崩溃 |

| **【Firebase RemoteConfig】网络异常时降级** | 断网环境下冷启动 App，触发域名替换场景 | 使用上次缓存的 RemoteConfig 配置或内置默认值，不崩溃 |
| **【Firebase RemoteConfig】备用域名配置为空** | Firebase 后台将备用域名字段置空，触发主域名屏蔽 | 有兜底处理逻辑，不崩溃；具体降级策略以技术方案为准（确认后更新） |
| **【离线包反查】离线包正常加载** | 进入使用离线包的 H5 页面 | 离线包正常加载，页面展示正常，加载速度符合预期 |
| **【离线包反查】域名替换后离线包反查** | 屏蔽主域名触发域名替换后，进入使用离线包的 H5 页面 | 离线包能通过反查功能正确映射到对应资源，页面正常展示，无资源 404 |

| | 遍历 App 内所有主要 H5 入口页面（充值页、活动页、个人中心等） | 各 H5 页面正常展示，业务功能正常，无回归问题 |
| **【兼容性】多设备/系统** | 分别在 iOS 和 Android 系统上执行域名替换核心场景（屏蔽主域名触发备用域名） | iOS 与 Android 行为一致，均能正确切换备用域名并正常访问 |
