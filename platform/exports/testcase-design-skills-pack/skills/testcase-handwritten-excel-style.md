# 手写体 Excel 合并风格（测试点 → 用例）

## 适用场景

- 用户提供了**自己写的参考用例** `.xlsx`（关心 **B/C 列纵向合并**、一条步骤下挂多条预期），并要求**新用例只依据测试点 + 需求**写成「差不多」的表，**禁止照抄参考用例的预期原文**。
- 目标产物仍走仓库脚本：`check_testcase_md.py` → `export_testcases_to_desktop.py`。

## 核心结论（迭代过程摘要）

1. **对照参考表结构**  
   用 `openpyxl` 查看参考 Sheet 的 `merged_cells`：常见形态是 **功能模块列大块纵向合并**；**测试步骤（case 步骤）列在「同一步、多预期」时再次纵向合并**，续行只在「预期结果」列换内容，步骤格在 Excel 里为空（合并到上一格）。

2. **导出脚本实际规则**（与 `脚本/export_testcases_to_desktop.py` 一致）  
   - 连续多行 **功能模块** 字段完全相同 → 合并 **A** 列。  
   - 连续多行 **测试步骤** 字段完全相同 → 合并 **B** 列。  
   - 四列表时 **对应测试点** 连续相同 → 合并 **D** 列；**预期结果列永远不合并**。  
   - 解析逻辑见 `脚本/testcase_md_table.py`：`测试步骤` 为空或属于续行记号时，会**继承上一条非空步骤**，从而使相邻行在内存里 `step` 相同 → 触发 **B 列合并**（等价于手写表里「同一步、多行预期」）。

3. **首版偏差**  
   若 Markdown 写成「长叙述测试步骤 + 每行不同措辞」，解析后每行 `step` 都不同 → 导出往往只有 **A 列合并**，**B 列几乎不合并**，与手写参考差异大。

4. **修正策略（与手写稿对齐）**  
   - **列数**：参考表若无「对应测试点」列，可用 **三列表** 导出；若用户要求**测试步骤不得与测试点逐字相同**，则改用 **四列表**，增加【对应测试点】列存放 Excel **原文**，【测试步骤】只写**操作型短句**（进入/点击/切换账号与数据前提等），二者分离。  
   - **测试步骤**：默认写**可执行操作**，不要复制测试点长句；需要合并 B 列时，同一测试点下的续行仍用 **`↑`** 继承上一条**操作描述**（不是继承测试点原文）。  
   - **一条测试点多条预期**：第一行写该步操作锚点；后续行「测试步骤」填 **`↑`**（或 `同上` 等 `CONTINUE_TOKENS`）使解析继承同一步 → **B 列纵向合并**；【对应测试点】在续行重复同一原文 → **D 列纵向合并**；每条预期单独一行、格末不收尾标点，遵守根 `SKILL.md` 速记与 `check_testcase_md.py`。  
   - **功能模块**：续行每行仍写**同一模块名**（与手写表「合并后只看见一块模块」等价，且保证 A 列连续相同可合并）；勿留空模块，否则 `Row.module` 为空会破坏 A 列合并段。

5. **验收方式**  
   - 跑 `check_testcase_md.py` 退出码 0。  
   - 导出后用脚本统计 `len(ws.merged_cells.ranges)`，与参考表**合并块数量级接近**（同需求、同测试点粒度下，本次家族房用例从约 **7** 块增至 **18** 块，与参考 `工作簿2.xlsx` 一致）。

6. **文风（与根 SKILL 一致）**  
   短句但要**完句可读**，像人工写用例；禁电报式过度缩写；禁冗长套话；只写核心动作与可验结果。

## Agent 操作清单

1. 读参考 xlsx：列名、是否有空 A 列、merged ranges 模式。  
2. 只抽取**合并模式**，不抄**预期文案**。  
3. 按测试点顺序列出一行一步；需拆预期处加 `↑` 行。  
4. 自检 + 导出桌面 xlsx。  
5. 若合并块明显少于参考：检查是否「一步一行一预期」过多，应把同一测试点下的可验断言拆成多行预期并配 `↑`。

## 与主流程关系

默认「测试点 → 用例」仍以根目录 `SKILL.md`（四列 + 对应测试点）为准。当用户**明确要求与手写 xlsx 版式一致**时，再启用本 Skill 的续行合并写法；若用户要求测试步骤勿与测试点逐字相同，优先四列把原文放进「对应测试点」列。
