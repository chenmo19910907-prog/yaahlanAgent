Open API

重新生成会使旧 Token 失效。

鉴权与响应格式

  • 所有接口均为 POST，Content-Type: application/json
  • 响应体统一为 { "code", "message", "data" }；业务成功时 code 为 OK
  • 401 表示 Token 缺失或无效；503 表示服务端未配置任何 Token

提交任务 · POST /task/submit

  • message（可选）：发给 Agent 的文字，可与 images / attachments 同传
  • images / attachments（可选）：附图或附件，格式同 Web POST /api/chat；每项含 data_base64、mime、name（扩展名决定图片或文件）
  • message 与有效 images / attachments 至少填一项（可只文字、只图/附件，或文字+图/附件一起）
  • conversation_id（可选，别名 session_id）：指定会话；省略则自动续用该 Token 对应的 API 会话
  • caller（可选，可省略）：不传时会话与 Agent 身份归属 Token 提供者（个人 ywa_ Token 为生成者的钉钉 staff_id）。BFF 代登录用户时可传 { "work_id", "name", "momoid" }；服务 Token 下按 work_id 隔离会话；个人 Token 仍以 Token 为准，name 仅补充展示名
  • callback_url（可选）：任务进入终态后 POST 推送，Body 与 query 成功时 data 相同；配置了 WEB_AGENT_OPEN_API_CALLBACK_SECRET（或服务 Agent Webhook Secret）时带 X-Webhook-Signature
  • 成功 data：task_id、conversation_id、status: "submitted"
  • 409：该会话仍有任务进行中，data 含当前 task_id
