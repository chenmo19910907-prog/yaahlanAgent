## 群里怎么用（发给团队成员）

在已添加 **企业机器人** 的群里：

```
@机器人 你的问题或任务
```

**示例**

| 场景 | 示例 |
|------|------|
| 问仓库 | `@机器人 platform 目录有哪些工具？` |
| 快捷导出 | `@机器人 导出 temporary_testcase/xxx.csv` |
| 环境检查 | `@机器人 环境检查` |
| 附图 | 发截图 + `@机器人 看这个页面有什么问题` |
| 带链接 | `@机器人 读这个文档 https://alidocs.dingtalk.com/...` |
| 中断任务 | `@机器人 中断操作`（仅打断本群当前任务） |
| 重新执行 | `@机器人 重新执行`（重跑本群上一条任务） |
| MOA 探活 | `@机器人 MOA检查` |
| 帮助 | `@机器人 帮助` |

**说明**

- 先回「已收到，执行中…」，完成后回结果
- 大表格/JSON 会自动导出到钉钉文档「智能工具导出」并回链接
- 未写「线上环境」时，只用测试环境脚本
- 执行机休眠或网关未运行时，`@` 会无响应

## 常驻运行（launchd，推荐）

```bash
cd platform/dingtalk_gateway

# 安装并启动（开机自启 + 崩溃自动重启）
./gateway_ctl.sh install

# 查看状态
./gateway_ctl.sh status

# 重启 / 停止
./gateway_ctl.sh restart
./gateway_ctl.sh stop

# 跟踪日志
./gateway_ctl.sh logs

# 健康检查（Bridge / MOA / 凭证）
./gateway_ctl.sh health
```

卸载：

```bash
./gateway_ctl.sh uninstall
```

**注意**：不要同时跑 `bot_echo.py`、`start_gateway.sh` 与 launchd，同一时间只能一个 Stream 连接。

## 凭证与安全

| 文件 | 说明 |
|------|------|
| `.env.local` | `CURSOR_API_KEY`、`DINGTALK_CLIENT_ID`、`DINGTALK_CLIENT_SECRET` |
| `config/executor.local.json` | 执行机登记（不入库） |

若 Client Secret 曾泄露，到 [钉钉开放平台](https://open.dingtalk.com/) → 应用 → **凭证与基础信息** → **重置 Secret**，只更新 `.env.local`。
